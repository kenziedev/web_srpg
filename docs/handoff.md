# 개발 인수인계

상태: 초기 골격 + 아군 행동 전술 연습장. **전체 전투 프로토타입 A~B 완료가 아니다.** 다른 AI나 개발자는 이 문서와 루트 AGENTS.md부터 읽는다.

## 구현된 것

| 영역 | 진입 파일 | 현재 동작 |
|---|---|---|
| 웹 앱 | `apps/web/src/ui/App.tsx` | 유닛 선택, 이동 예정·취소·확정, 공격·정비·회복, 초기화 |
| 지도 | `apps/web/src/game/BattleMap.tsx` | Phaser 도트 임시 지도, 드래그·휠 카메라, 범위·HP 표시 |
| 콘텐츠 | `packages/content/data/two-crossings.json` | 설계 맵 20×15, 초기 21기, 예약 증원 데이터 3기 |
| 검증 | `packages/schema/src/index.ts` | 타입·배치·참조·이동 불가 지형·상성 중복 검증 |
| 이동 | `packages/core/src/movement.ts` | 지형 비용, 아군 통과·점유 종료 금지, 비행, 결정론적 경로 |
| 교전 | `packages/core/src/combat.ts` | 지휘 보정, 정수 비율 피해, 병종 상성, 반격 사거리 |
| 명령 | `packages/core/src/commands.ts` | 이동+행동 원자 적용, 동시 교전·퇴각, 중복/오래된 명령 거절 |
| 재현 | `packages/sim/src/smoke.ts` | 미라 첫 봉화 접근·명령 미변경·동일 명령 재현 스모크 |

React 상태가 현재 세션의 BattleState를 소유한다. 선택한 경로와 액션으로 `evaluate`를 호출해 미리 보며, 확정할 때 `apply`를 호출한다. 두 함수는 같은 코드 경로를 쓴다. Phaser는 상태를 그릴 뿐 규칙을 실행하지 않는다. `ActCommand.path`는 **출발점을 제외한 진입 타일 목록**이며, 빈 배열은 제자리 행동이다.

패키지 흐름: schema ← content, schema ← core, core+content ← web/sim. 워크스페이스 패키지는 소스 TypeScript를 export하고 Vite/tsx가 처리한다. 별도 배포용 라이브러리 빌드는 아직 필요하지 않다.

## 아직 없는 것

- 적 AI, 페이즈 전환, NPC 이동, 봉화 점령, 증원 실행, 제한 라운드·승패 판정.
- 페이즈 시작 인접·거점 회복, 독·침묵, 피해 마법, EXP·캠페인 정산.
- 세이브·로드·파일 백업. 현재 새로고침 시 초기 상태로 돌아간다.
- 전직·고용·장비·6장 캠페인, 사운드·최종 아트·연출, 온라인.
- 전체 적 위협 오버레이, 이동 예정 지휘관 위치에 따른 범위 시각 갱신, 줌·완전한 키보드 타일 조작.

현재는 아군 한 페이즈 연습이므로 행동을 모두 소모하면 연습 초기화로 다시 시작한다. 적은 공격받거나 정보가 표시될 뿐 자동 행동하지 않는다. 증원은 데이터에만 있고 최초 맵에는 생성하지 않는다. `canHeal`은 첫 맵 지원 지휘관용 초기 능력 필드이며, 전체 스킬 시스템으로 확정하지 않는다. `BattleState`에 아직 라운드·목표·기여 필드가 없으므로 아래 순서로 추가한다.

## 다음 작업 순서

### P01. 페이즈와 회복

`BattleState`에 round/phase, `Command`에 EndPhase를 추가하고 아군→적→NPC→종료를 코어에서 처리한다. `ActCommand` 로그는 명령 유니온으로 확장한다. 적 AI를 붙이기 전에는 테스트 픽스처로 적/NPC 페이즈를 진행한다.

수용 기준: C03의 회복 큰 값 하나 적용, C05 정비 유지, 해당 진영 행동권만 초기화, 동일 명령 로그 재현. 독 기능을 함께 구현하지 않는다면 C04는 보류로 명시한다. UI의 “다음 라운드” 버튼으로 모든 유닛 acted를 직접 초기화하지 않는다.

### P02. 시나리오 목표·호송·증원

첫 맵 문서의 시간표·예비 증원 칸·호송 경로·최대 10라운드를 JSON 데이터로 확장한다. 보호 대상 사망의 패배 우선, 봉화 점령, 증원 전체 배치 가능성, NPC 도로 이동을 구현한다.

수용 기준: C08/C12/C13, 방해 없을 때 9번째 NPC 페이즈 탈출, 봉화 3라운드 종료 점령이면 증원 취소, 증원 칸 점유 시 기존 유닛 보존. 코어는 특정 캐릭터 ID를 알지 않고 목표 데이터의 참조를 사용한다.

### P03. 기초 적 AI

같은 `reachable/evaluate/apply`를 사용해 후보를 생성하고 목적·피해·반격·지휘 유지로 점수를 매긴다. 고정된 동률 순서와 후보 예산을 사용한다. 첫 버전부터 완벽한 협동 탐색을 구현할 필요는 없지만 행동 불가 시 반드시 종료한다.

수용 기준: 부대가 길에 막혀도 무한 루프 없음, 노출 지휘관·상성 우위·안전 정비 국면 테스트, 같은 상태에서 같은 명령. 실시간 타임아웃으로 수 선택 결과를 바꾸지 않는다.

### P04. 복구 저장과 첫 맵 완주

IndexedDB 저장 어댑터를 web에 두고 코어 상태·명령·규칙/콘텐츠 버전을 저장한다. 현재 행동 데모를 `BattleController` 또는 hook으로 분리해 UI와 페이즈 자동 진행을 연결한다.

수용 기준: 확정 행동 직후 새로고침 복구, 오류 파일 가져오기로 정상 저장 훼손 없음, 원래 상태를 바꾸지 않는 미리보기, 최소 2경로로 첫 맵 완주 로그. 이후에만 성장·인터미션으로 넘어간다.

## 다음 AI에게 그대로 전달할 작업 지시

```text
이 저장소의 AGENTS.md, README.md, docs/handoff.md와 docs/combat-rules.md를 읽어라.
현재는 아군 행동 연습장이며 전체 전투는 미완성이다.
이번 작업은 handoff의 P01(페이즈와 회복)만 구현한다.
코어/콘텐츠/화면 경계를 유지하고 실패 명령 상태 불변성과 결정론을 보장한다.
C03/C05 관련 테스트를 추가하고, pnpm check 및 pnpm build를 실행한다.
UI를 변경했다면 pnpm test:e2e도 실행하고 화면을 확인한다.
완료한 범위와 남은 항목을 handoff에 갱신한다. P02 이후로 범위를 임의 확장하지 않는다.
```

## 검증과 운영 메모

`pnpm check`: 타입 검사 → 코어/콘텐츠 테스트 → 콘텐츠 검증 → 재현 스모크 → 코어 경계 검사.
`pnpm build`: 타입 검사 후 production Vite 빌드.
`pnpm test:e2e`: Chromium에서 지도 마운트·선택·미리보기 취소·확정·초기화 확인. 최초 한 번 `pnpm exec playwright install chromium`가 필요하다.

성능 예산은 아직 검증하지 않았다. 자동 테스트 통과를 실제 전투 재미나 캠페인 완성으로 해석하지 않는다. 도트 도형은 프로젝트 내 코드로 작성한 임시 표현이며 원작 에셋을 포함하지 않는다.

초기 골격 검증 기록(2026-09-08, Windows / Node 24.16.0): `pnpm check` 통과(24개 규칙·콘텐츠 테스트 포함), `pnpm build` 통과, Chromium E2E 2개 통과. 지도 클릭으로 창병 이동 후 기병 공격 시 예측 5 피해와 실제 HP 5가 일치하는 것을 확인했다. 화면 PNG를 직접 확인했다. 현재 번들은 JS gzip 약 450KB이며 Phaser 포함 단일 청크 크기 경고가 남는다. 이는 실패가 아니지만 후속 화면이 늘어날 때 코드 분할을 검토한다. 원격 CI와 다른 브라우저의 실행은 별도 확인 대상이다.

기술 확인 자료: [Phaser 공식 프로젝트 템플릿](https://docs.phaser.io/phaser/getting-started/project-templates), [Vite 시작 문서](https://vite.dev/guide/). 실제 설치 버전은 각 package.json과 pnpm-lock.yaml을 기준으로 한다.
