# 개발 인수인계

**외부 아트 적용(2026-09-14):** 고전 PC SRPG 분위기로 Toen의 지형·병사, Exewin의 마법사·성직자, ZeNeRIA29의 주인공 3인 초상, Ravenmore 장비와 Painterly 마법 아이콘을 연결했다. 창·하단 HUD는 청색·상아색·금색으로 통일했고, 상세 교전과 마법 연출도 같은 병사 그림을 사용한다. [아트 방향](art-direction.md)과 [원본·라이선스 장부](asset-sources.md)가 현재 그림 기준이다. 안내 창에 출처를 표시하며 원본 PNG를 Vite 정적 자산으로 제공한다. 코어·콘텐츠·저장 포맷은 바꾸지 않아 규칙 0.8 저장과 호환된다. 아래의 코드 도형만 사용하던 아트 절은 이전 구현 이력이다.

아트 로컬 검증: `pnpm check`(401개 검사·두 클리어 경로·경계 검사), `pnpm build`, `pnpm build:srpg`, 전체 Chromium **71개**가 통과했다. 이미지 다운로드 실패 시 자체 지형으로 진행·저장 복구, 이동 잔상, 실제 메테오 후 지형 합성 1→2회와 저장 동등성, 데스크톱·390px 장비/마법/상세 전투 화면을 확인했다. 이미지 전송을 포함한 프로덕션 시작은 10Mbps·100ms 지연의 새 Chromium 컨텍스트 5회에서 중앙값 **1.79초**, 최대 **1.87초**, 저장 복구 최대 **0.64초**였다([측정 결과](../artifacts/art-browser-performance.json)). 초상 네트워크 수신까지 측정하며 별도 디코딩·페인트 완료, 저사양 실기기 성능은 포함하지 않는다. 공개 검증은 아래 이전 0.8 배포 기록과 구분하며 새 아트 배포 결과는 추가 기록한다.

[Pages 배포 실행](https://github.com/kenziedev/kenziedev.github.io/actions/runs/34618075268)이 성공했다. `/srpg`의 `/srpg/` 이동, HTML·JS·CSS의 HTTP 200·MIME·SHA-256 일치와 실제 Chromium의 전장·성장·장비·행동 후 새로고침 복구를 확인했다. 블로그를 먼저 방문해 루트 서비스워커가 활성화된 상태에서도 게임을 실행했고 게임 경로가 블로그 캐시에 들어가지 않았다. 공개 시작/성장 화면 PNG와 오류 없는 콘솔을 확인했다.

이전 0.7 CI 기록: 소스의 첫 원격 CI는 검사·두 빌드에 성공했으나, 마법 3종을 한 테스트에서 실행하는 사례 하나가 30초 제한을 넘어 E2E 50개 성공·1개 시간 초과였다. 마법별 독립 사례로 분리하여 기존 검증·시간 제한을 유지했고 해당 3개가 로컬에서 통과했다. 전체 E2E 등록 수는 53개이며 실패 시 CI 결과물을 7일 보관한다. 이 변경은 테스트·CI 설정에만 해당하며 공개 게임 번들은 바뀌지 않는다. 분리 후 원격 CI 결과는 해당 커밋의 Actions 실행에서 확인한다.

상태: 실행 규칙 **0.8**의 공통 시스템 통합. 기존 마법 35종·아이템 34종·성장·18직업에 정식 출격 준비·고용·상점·분리 자금·생존 계약·6계열 마스터리·수동 3슬롯·준비 복구·적 물리 위협·줌·키보드 조작을 연결했다. 이번 실행 순서와 수용 기준은 [남은 작업 계획](remaining-work-plan.md)을 따른다. 새 맵·시나리오·전용 적 전술은 후순위이며 전체 캠페인이나 사람 플레이 검증을 완료한 상태는 아니다. 최신 통합 검증·배포 상태는 이 문서의 0.8 절을 우선한다.

React 상태가 현재 세션의 BattleState를 소유한다. 선택한 경로와 액션으로 `evaluate`를 호출해 미리 보며, 확정할 때 `apply`를 호출한다. 두 함수는 같은 코드 경로를 쓴다. Phaser는 상태를 그릴 뿐 규칙을 실행하지 않는다. `ActCommand.path`는 **출발점을 제외한 진입 타일 목록**이며, 빈 배열은 제자리 행동이다.

패키지 흐름: schema ← content, schema ← core, core+content ← web/sim. 워크스페이스 패키지는 소스 TypeScript를 export하고 Vite/tsx가 처리한다. 별도 배포용 라이브러리 빌드는 아직 필요하지 않다.

## 후속 콘텐츠·제품 작업

- 새 장·6장 캠페인·추가 출격 캐릭터·E1/E3 전용 전술·난이도별 배치. 현재는 같은 맵에서 공통 시스템을 검증한다. 초기 EXP나 능력치를 올려 전직 조건을 우회하지 않는다.
- 여러 장에서 Lv10에 도달하는 성장 속도와 마스터리 운용 검증. 현재 한 맵의 보상은 반복 지급하지 않으므로 새 장 없이 자연스럽게 모든 성장 경로를 체험할 수는 없다.
- 사람 5명의 두 경로 플레이·재미/밸런스 관찰, 실제 Safari/Firefox와 저사양 기기의 시작·프레임·누수 예산 검증. 자동 Chromium·Node 코어 성능 측정과 구분한다.
- 0.7 진행 중 전투의 자동 마이그레이션. 전용 구버전 실행기 없이 버전만 바꾸지 않으며 기존 원본 백업을 제공한다.
- 미확정 원작 수치·직업별 장착 행렬의 완전 복원, 최종 아트·사운드·온라인·클라우드 저장. 독·해제는 확인되지 않은 PC판 목록에 임의 추가하지 않는다.

## 이전 고전 화면 아트 갱신 이력

지형 도형을 `pixelTerrain.ts`로 분리했다. 숲 수관·그림자, 강둑·물결, 도로 바퀴 자국, 목교, 언덕 단차, 회복소와 봉화탑을 24px 논리 픽셀로 그린다. 장면 생성 때 텍스처로 만들어 선택·행동마다 지형을 다시 그리지 않는다. 병사·기병 대형을 키우고 비병 날개를 추가했다.

`Portrait.tsx`는 투구·궁병·일반형의 코드 SVG 초상이며 캐릭터별 완성 아트는 아니다. UI는 청색 창과 금속 테두리로 정리했다. 출처·구조·남은 아트 작업은 [아트 방향](art-direction.md)을 따른다. 외부 에셋과 신규 의존성은 없다. 규칙·좌표·피해·클리어 로그는 변경하지 않았다.

검증: `pnpm check`(50개 규칙·콘텐츠 테스트와 143명령 클리어 재현), `pnpm build` 통과. Chromium은 동시 실행 중 시간 초과가 있어 `pnpm test:e2e --workers=1`로 재검증하여 7개 모두 통과했다. 실제 초기 화면·초상·지형·병사 대형을 PNG로 확인했다. 빌드 JS gzip은 약 459KB이며 기존 Phaser 청크 경고는 남아 있다.

턴 종료는 EndPhase 명령으로 처리한다. 남은 미행동 부대가 있으면 확인하며, 적은 자동 이동·공격·정비 후 종료한다. 적 페이즈 종료로 NPC에 진입할 때 호송대를 자동 이동한다. NPC 종료 명령은 점령·승패·증원을 판정한 뒤 다음 라운드로 넘어간다. 보호 대상 사망은 모든 확정 행동 직후 우선 판정하며, 결과 확정 후 전투 명령은 거절하며, 허용되는 성장·재연습 명령만 별도 경로로 처리한다. `BattleState.round`는 1부터 시작하고 NPC→아군 전환 때 증가한다. 목표 상태는 mission, 종료 결과는 outcome에 저장한다. 기여·정산·해금 마스터리와 선택 슬롯은 progression에 저장한다. 여섯 패시브 밖의 추가 스킬은 콘텐츠 후속 범위다.

### P03. 기초 적 AI — 기본 동작·E2 작전 구현, E1·E3 보완 필요

같은 reachable/evaluate/apply로 도달 칸×공격·대기·정비 후보를 평가한다. 피해·반격·지휘 보정·지휘관 처치·현재 사거리 위협을 반영한다. 용병 우선, ID와 이동 비용·좌표 순서로 동률을 고정한다. 유닛당 한 행동으로 종료하며 시계를 참조하지 않는다.

P03a: E2 경비 부대는 콘텐츠의 `enemyPlans` 단계표를 공유한다. 1~2라운드에는 북쪽 여울 동쪽 (11,3), 3라운드부터 남쪽 호송로 (11,10)에 접근한다. 코어는 현재 라운드로 작전을 조회하며, 지형 진입 비용과 적 점유를 반영한 역방향 최단 비용으로 이동 후보를 평가한다. 우회로도 고려하고, 도달 불가능하면 기존 적 접근 평가를 사용한다. 공격·반격·정비·지휘 보정 평가는 유지하므로 목표로 무조건 돌진하지 않는다. UI는 코어 조회 결과로 현재 작전과 다음 전환을 표시한다.

현행은 유한 전체 후보 1수 평가다. E1·E3의 목표별 행동, 설계의 상위 12개 2수 탐색·성격별 JSON 가중치·협동 회복은 아직 없다. 테스트는 작전 전환 경계·부대 공유, 지형 우회와 비용, 점유 목표, 안전한 처치, 단절 목표, 동일 상태 결정론과 실패 명령 불변성을 확인한다. 노출 지휘관·상성·안전 정비 개별 국면과 최대 규모 성능 측정은 보완 대상이다.

### P04. 복구 저장과 첫 맵 완주 — 구현·자동 재현 완료, 사람 검증 남음

IndexedDB 어댑터를 web에 두고 확정 행동·페이즈 전환·턴 종료 확인 경계마다 저장한다. 최신 자동 저장과 직전 정상 저장을 하나의 트랜잭션으로 쓰고 같은 탭의 쓰기/읽기 요청은 직렬화한다. 저장 완료 전 성공을 표시하지 않으며 다음 자동 명령도 기다린다.

새로고침 시 저장 읽기를 마친 후 입력·자동 큐를 허용한다. 용병 자동 행동의 진행 여부와 옵션도 저장해 확정한 턴 종료가 이어진다. 연출·선택·미리보기는 복구하지 않는다. 상단 연습 초기화는 전체 진행의 초기 상태를 저장한다. 결과창 재도전과 정산 뒤 재연습은 성장·장비·보상 기록을 유지하며 전장을 다시 배치하고, 두 동작 모두 기존 예약 동작을 무효화한다. 가져오기는 검증과 디스크 기록이 성공한 후에만 현재 전투를 교체한다.

최신 저장이 손상되면 직전 정상 저장으로 복구하고 원본 슬롯은 읽기만 한다. 양쪽 모두 읽을 수 없으면 경고와 함께 새 전투를 열되 자동 덮어쓰기를 중지한다. 파일 가져오기, 현재 전투 다시 저장, 연습 초기화는 명시적인 교체 동작이다. 저장소 차단·용량 부족·쓰기 중단은 화면에 유지하고 현재 메모리 상태의 파일 내보내기를 제공한다.

수용 사례: 확정 교전 연출 도중 새로고침 복구, 미리보기 저장 불변, JSON 백업/복구, 오류 파일 기존 상태·슬롯 불변, 쓰기 실패 원자성, 손상 최신의 직전 복구, 용병/적 자동 행동 재개, 초기화 후 복구. 현행 AI 상대 봉화 경로 153명령과 정면 방어 경로 160명령을 동일 초기 콘텐츠로 재현한다. 두 경로 모두 9라운드 승리·호송 HP 10·아군 12기 생존이다. 사람의 재미 검증이나 외부 5명 관찰을 완료한 것은 아니다.

P03a에서 결정론적 AI 정책·콘텐츠가 바뀌어 rulesVersion을 0.3으로 올렸다(schemaVersion은 1 유지). 이전 0.2 저장을 자동 변환하거나 덮어쓰지 않는다. 저장창의 기존 저장 원본 백업은 최신·직전 슬롯을 읽고 버전·내용·체크섬을 재작성하지 않은 JSON으로 내보낸다. JSON으로 표현할 수 없는 값이나 2MiB 초과 데이터는 오류를 표시하며 원본을 보존한다. 현재 메모리 전투 내보내기와 구분하며 저장소가 차단돼도 현재 전투 백업은 가능하다.

저장 형식: schemaVersion 1, rulesVersion, contentHash, revision, lastCommandId, initialState, commands, battle, continuation, updatedAt, checksum. 엄격한 스키마·참조·버전·체크섬과 전체 apply 재현 결과를 비교한다. 현재 콘텐츠의 초기 배치만 허용하고 마이그레이션하지 않는다. 키 정렬 JSON의 UTF-8 FNV-1a는 우발적 손상 탐지용이며 인증/치팅 방지 수단이 아니다. 파일 상한 2MiB·명령 1024개이며 현재 10라운드 검증판을 수용한다. 성장·기여·시나리오 보상 장부는 현재 battle.progression에 포함한다. 0.8은 정식 경제 상태와 수동 3슬롯·출격 준비 체크포인트를 추가한다. 새 장 진행 필드는 후속 범위다. 재연습·재도전에서도 전역 명령 1,024개 상한을 공유하므로 한 저장 기록에서 무제한 반복은 보장하지 않는다.

## 검증과 운영 메모

`pnpm check`: 타입 검사 → 코어/콘텐츠/저장 포맷 테스트 → 콘텐츠 검증 → 재현 스모크 → 실제 적 AI 상대 두 경로(153/160명령) 클리어 재현 → 코어 경계 검사.
`pnpm build`: 타입 검사 후 production Vite 빌드.
`pnpm test:e2e`: Chromium에서 지도 마운트·선택·미리보기 취소·확정·초기화 확인. 최초 한 번 `pnpm exec playwright install chromium`가 필요하다.

성능 예산은 아직 검증하지 않았다. 자동 테스트 통과를 실제 전투 재미나 캠페인 완성으로 해석하지 않는다. 도트 도형은 프로젝트 내 코드로 작성한 임시 표현이며 원작 에셋을 포함하지 않는다.

초기 골격 검증 기록(2026-09-08, Windows / Node 24.16.0): `pnpm check` 통과(24개 규칙·콘텐츠 테스트 포함), `pnpm build` 통과, Chromium E2E 2개 통과. 지도 클릭으로 창병 이동 후 기병 공격 시 예측 5 피해와 실제 HP 5가 일치하는 것을 확인했다. 화면 PNG를 직접 확인했다. 현재 번들은 JS gzip 약 450KB이며 Phaser 포함 단일 청크 크기 경고가 남는다. 이는 실패가 아니지만 후속 화면이 늘어날 때 코드 분할을 검토한다. 원격 CI와 다른 브라우저의 실행은 별도 확인 대상이다.

기술 확인 자료: [Phaser 공식 프로젝트 템플릿](https://docs.phaser.io/phaser/getting-started/project-templates), [Vite 시작 문서](https://vite.dev/guide/). 실제 설치 버전은 각 package.json과 pnpm-lock.yaml을 기준으로 한다.

## 2026-09-09 턴 종료·고전 UI 변경

큰 제목과 상시 카드 목록을 작은 상단 메뉴, 전장 위 파란 명령창, 하단 능력치·예측창으로 교체했다. 맵은 48px 타일과 최대 960×720 전장을 유지한다. 작은 창은 카메라로 이동한다. 임시 초상·병사·기병·지휘관 깃발은 코드 도형이다. N 다음 부대, E 종료, C 지휘 범위, Enter 확정, Esc 취소를 제공한다. 확인창의 단축키는 배경 부대를 조작하지 않는다.

검증: pnpm check 통과(33개 규칙·콘텐츠 테스트), pnpm build 통과, Chromium E2E 5개 통과. E2E는 지도 공격 예측, 취소·초기화, 미행동 종료 확인, 전체 행동 후 종료, 적 턴→다음 턴, 적 턴 중 초기화, 1280×720 배치를 확인한다. 생성 화면의 파란 메뉴·하단 HUD·도트 병사와 전장 배치를 직접 확인했다. 성능 예산·전투 재미 검증은 별도다. Phaser 단일 청크 크기 경고는 남아 있다.

## 2026-09-09 첫 맵 목표 구현

- 호송대는 NPC 진입 때 고정 경로에서 이동비 내 마지막 빈 칸으로 이동한다. 아군 통과·적 차단·점유 끝 칸을 코어의 동일 함수로 예측하고 실행한다. 지도와 목표창에 다음 위치와 방해 유닛 ID·이유를 표시한다.
- 지휘관의 라운드 종료 점령을 기록한다. 3라운드 종료 점령은 같은 시점 증원을 취소한다. 보류 중 점령도 취소하며, 생성된 부대는 제거하지 않는다.
- 증원은 주·예비 칸을 부대 전체로 탐색한다. 하나라도 배치 불가 또는 슬롯 초과면 기존 유닛을 보존하고 다음 종료에 재시도한다. 등장 다음 적 턴부터 행동한다.
- 결과창에 승패 사유·라운드·보너스 달성과 재도전을 제공한다. 보너스는 기록만 하며 캠페인 자금을 지급하지 않는다. 종료 후 자동 타이머와 코어 명령을 막는다.
- 기본 적 AI의 부대별 목표 계획은 여전히 P03 보완 대상이다. C04 상태 이상, 저장·캠페인은 포함하지 않았다.

상세창은 확정 전/후 BattleState와 BattleEvent만 읽고, 양쪽 HP·병력 수·반격 가능 여부를 표시한다. 용병은 교전 전 HP만큼 병사를 그린 뒤 확정 후 HP만큼 남기며 지휘관은 한 명을 그린다. 접근·돌진/투사체·타격·병력 감소 연출은 CSS/SVG이며 원본 게임 에셋을 사용하지 않는다. 일반 4.2초, 빠른 진행 1.5초 후 복귀한다. 건너뛰기·Space·Enter·Esc는 현재 연출만 해제하고 명령을 재실행하지 않는다. 모달 포커스를 가두며 reduced-motion에서는 움직임을 줄인다.

## 상세 전투 병사 동작 수정

대형 전체 이동만 있던 상세창에 80단계 재생 타임라인을 추가했다. 대형 정렬→달리기→무기 공격/반격→피격→결과 순서로 각 병사의 다리·팔·창/검/활 자세와 비병 날개를 바꾼다. 병사별 프레임을 엇갈리게 하고 피격과 탈락을 표시한다. HP 감소는 확정 후 상태를 재생 후반에 표시하며 추가 명령은 실행하지 않는다.

기존 reduced-motion CSS는 대형·타격 효과 애니메이션을 모두 끄므로 정지 화면처럼 보일 수 있었다. 이제 큰 이동은 계속 줄이되 SVG 자세 전환과 단계·HP 표시는 유지한다. requestAnimationFrame은 창 해제 시 취소하며 프레임은 코어 상태·결과에 영향을 주지 않는다. 일반/움직임 줄이기 양쪽에서 다리와 무기의 실제 transform 변화까지 브라우저 테스트로 확인한다.

검증: `pnpm check`(규칙·콘텐츠 56개, 임무 재현·경계 검사), `pnpm build` 통과. 전체 Chromium E2E에서 기존 12개와 일반 동작 검사가 통과했으나 짧은 공격 구간을 600ms 폴링하던 움직임 줄이기 검사는 실패했다. 브라우저 MutationObserver로 전투 중 실제 SVG transform을 기록하도록 개선한 뒤 상세 전투 5개를 재실행해 모두 통과했다(전체 14개 사례 확인). 최종 `pnpm typecheck` 통과. 실제 브라우저 화면에서 대형 배치, 공격 자세와 피격·병력 감소를 확인했다. 기존 Phaser 청크 크기 경고는 유지된다.

### S02/S03 — 구 PC판 나머지 마법·소환·장비와 전투 준비, rulesVersion 0.6

런타임 `two-crossings.json`에 일반 마법 26종과 소환 마법 9종, 소환 템플릿 9종, 아이템 34종을 등록했다. 이전 참조 JSON과 실제 실행 데이터의 역할은 유지한다. 검증판은 아이템 한 개씩을 소유하며, 메사이얀 소드·룬스톤은 경험치·전직 시스템이 없어 사용을 막고 이유를 보여 준다. 나머지 32종은 소유 수량·슬롯·병종 제한을 통과하면 장착 효과를 제공한다. 크로스는 성직 병종 전용이므로 현재 초기 지휘관 3명에게 장착할 수 없다. 원작의 나머지 직업별 장착 행렬은 미확정이며 현재 프로젝트의 지휘관 공통 장비로 다룬다.

전투 상태의 원본 능력치를 바꾸지 않고 `effectiveUnit`으로 장비·강화·약화·지휘·MP·사거리·부대 이동/저항을 계산한다. 원작 MDF는 현재 RES와 단위가 달라 `floor(MDF/10)`으로 환산했다. 오브는 MP 비율을 유지하며 장착·해제 때 내림 처리해 반복 교체로 MP를 얻지 못하게 한다. 지휘 범위는 기존 프로젝트 상한 4를 적용한다. 완드/로드의 불확실한 마법 피해 방향, 다크 로드·그레이프 닐의 충돌하는 MDF 효과는 적용하지 않고 아이템 설명에 남겼다.

상태 성공은 저장된 시드·revision·시전자·대상·마법 ID로 재현하며 예측·취소가 상태를 바꾸지 않는다. 강화·약화는 다음 시전자 진영 페이즈 시작 전 만료하며, 같은 효과의 위력을 누적하지 않는다. 참은 부대의 원래 진영을 보존하고 기한에 복구하며 남아 있는 어택·프로텍션·레지스트·퀵 강화도 지운다. 메테오·어스퀘이크는 콘텐츠의 파괴 가능한 지형만 바꾸며 변화는 이동·전투·AI·렌더링·저장에 반영된다. 턴 언데드는 적 언데드 용병만 제거한다. 텔레포트는 대상 부대와 도착 칸을 선택하고 부대 전체의 합법 배치가 가능할 때만 적용한다. 어게인은 시전자·호송대를 제외한 이미 행동한 부대원에게 라운드당 한 번 재행동을 준다. 소환은 시전자당 한 기이며 교체·주인 사망에 따른 정리를 처리하고 생성 페이즈에는 행동하지 않는다.

`equip`·`train`은 첫 전투 `act` 또는 `endPhase` 전 준비 중에만 허용한다. 현재 인벤토리는 소유 총량이며 장착 시 소모하지 않는다. 일반 마법 26종과 일반 소환 6종은 연습 마법 편성으로 고르고, 장비 전용 소환 3종은 해당 장비로 얻는다. 고비용 마법은 최대 MP 부족 이유를 표시하며, 현재 성장 시스템을 우회하여 MP를 늘리지 않는다.

저장 형식 버전은 1, 실행 규칙은 0.6이다. 상태 효과·지형 변경·소유 장비·시드 필드는 필수이며, 장착·소환 소유·어게인 적용 라운드·텔레포트 목적지·준비 명령을 엄격히 검증하고 전체 명령 재생과 비교한다. 이전 0.2~0.5 저장의 원본 보존과 덮어쓰기 방지는 유지하며 자동 변환하지 않는다.

## 2026-09-11 S04/S05 경험치·레벨업·전직, rulesVersion 0.7

`experience.ts`는 실제 확정 피해·격파·퇴각·마법 회복에서 기여를 기록한다. 용병과 소환물의 기여는 원래 출격한 아군 지휘관에게 귀속한다. 피해 HP당 2 EXP는 적 개체당 20, 마법 회복 HP당 2 EXP는 지휘관당 30까지 배율 전에 제한한다. 용병 직접 격파 20·지휘관 60·살아서 퇴각한 용병 5를 구별하며 반격과 동시 격파도 원인별로 계산한다. 적 소환물과 조종 중 아군 공격으로 반복 EXP를 얻지 못한다. 정비·자동 회복·강화·소환 자체에는 EXP가 없다.

메사이얀 소드는 기여 발생 순간 장착한 소유 지휘관의 전투 기여를 2배로 만들고, 고정 클리어 180은 배율에서 제외한다. 승리 시 최초 출격 지휘관마다 한 번 정산하며 전투불능 지휘관도 지속 명부에 보존한다. 패배는 기여를 폐기한다. 같은 시나리오의 클리어 보상과 전투 기여는 다시 지급하지 않는다. 전투 중에는 기존 유닛 능력치·HP·피해 예측이 바뀌지 않으며 성장 결과는 정산 뒤 명부에 적용한다.
