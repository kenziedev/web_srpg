# 정식 작전 준비·고용·경제 — rulesVersion 0.8

`practice`는 기존 연습장이다. 초기 맵·배치·기본 능력치·미라의 네 마법·아이템 34종 소유를 유지하며 자유로운 연습 마법 편성을 제공한다. `operation`은 같은 맵을 예산과 학습 조건으로 준비한다. 두 모드는 별도의 초기 상태에서 시작하며 연습 아이템·성장을 정식 작전으로 옮기는 명령은 없다. 저장 검증도 선택한 모드의 초기 상태와 전체 명령 재생을 비교한다.

## 콘텐츠와 준비

`scenario.preparation`은 장비 자금·소유품·작전비·고정 용병 슬롯·상점·첫 승리 보상을 지정한다. 현행 초기 장비 자금은 300, 소유품은 없음, 작전비는 1,200이다. 기존 보병 3·창병 3·궁병 3의 고용비 합계는 1,020으로, 할인이나 보너스 없이 기존 편성을 사용할 수 있다. 초기 지휘관 능력치와 아홉 용병의 ID·좌표·능력치는 바꾸지 않았다.

`mercenaryTemplates`의 일곱 병종은 전투 규칙 문서의 스탯과 고용비를 쓴다. 보병 100·창병 110·기병 160·궁병 130·비병 220·수병 140·성직병 150이며 언데드는 고용할 수 없다. 각 직업의 `hireTemplateIds`가 허용 목록이다. 두 번째 직업의 목록은 제작 계획의 분기를 따르며 기본 직업은 현재 편성과 역할을 유지하는 두 병종부터 제공한다. 고용 슬롯은 기존 용병 ID를 유지하고 병종만 교체하며 지휘관 변경·추가 슬롯은 제공하지 않는다.

`hire`는 슬롯의 용병을 교체하거나 비운다. 작전비는 전체 편성 견적에서 계산하며 준비 중 취소·교체는 전액 환불된다. 부족한 예산·직업 제한·잘못된 참조·배치 불가능은 전체 명령을 거절한다. `startBattle`로 편성과 배치를 확인해야 이동·행동·턴 종료가 가능하다. 출격 후에는 고용·상점·장비·마법·마스터리 변경을 막는다. 정식 마법 편성은 `progression.learnedSpellIds`에 기록된 마법만 선택할 수 있다.

## 상점과 보상

장비 자금은 고용 작전비와 별도다. 상점은 로컬 구 PC판 참조 목록에서 구매 가격이 기록된 아이템을 제공하며 판매 가격은 구매가의 절반을 내림 처리한다. 가격 없는 스토리 아이템은 상점 거래를 제공하지 않는다. 초기 자금·전투 보상과 판매 비율은 프로젝트 규칙이며 원작 경제를 복원한 값이 아니다.

`buy`·`sell`은 양의 정수 수량만 허용한다. 구매는 실제 장비 자금을 쓰고 소유 수량을 늘린다. 판매는 장착 중인 수량을 제외한 소유품만 줄인다. 장착·해제로 물건을 복제하지 않으며 구매와 재판매로 이익을 만들 수 없다. 아이템 수량은 9,999, 장비 자금은 10억을 상한으로 한다. 보상으로 상한을 넘는 분량은 지급하지 않고 실제 지급량을 정산에 표시한다.

현행 첫 승리에는 장비 자금 400과 스몰 실드 1개를 지급한다. 달성한 보너스 목표마다 지원금 100을 더하며 최대 200이다. EXP의 `rewardedScenarioIds`와 같은 첫 승리 판정을 사용하므로 같은 맵을 반복해도 장비 자금·아이템·지원금을 다시 받지 않는다. 강화 장비나 높은 MP 마법을 먼저 열기 위해 초기 EXP·스탯을 올리지 않는다.

## 생존 계약과 재도전

이번 구현은 **지원금과 생존 계약을 다음 출격에 적용**한다. 제작 계획의 다음 장 전용 원안을 현재 한 맵에서 검증할 수 있게 조정한 규칙이며 새 캠페인 장은 만들지 않았다. 첫 승리의 지원금은 다음 준비에 한 번 더하고 사용하지 않은 작전비는 이월하지 않는다. 지원금 200을 받은 뒤의 다음 출격은 예산 1,400이며, 그 뒤 반복 승리로 지원금이 다시 생기지 않는다.

승리 때 살아 있는 원래 용병 슬롯을 같은 지휘관·용병 템플릿·수량으로 집계한다. 다음 출격에서 해당 수량만 20% 할인하며 초과 수량이나 다른 지휘관·병종에는 정가를 적용한다. 지휘관 사망으로 퇴각한 용병과 매혹한 적은 계약 대상이 아니다. 이전 계약을 누적하지 않고 새 생존 기록으로 교체하며 현재 직업이 고용하지 못하는 병종의 할인은 적용하지 않는다.

`operation.checkpoint`는 이번 준비에 진입한 시점의 성장 명부·인벤토리·장비 자금·작전비·계약·기본 편성을 저장한다. 패배 뒤 `deploy`는 이 기록으로 돌아가므로 준비 중 구매·판매·고용 교체·소모·전직을 함께 되돌린다. 이전 승리에서 얻은 성장·보상은 다음 준비 체크포인트에 이미 들어 있으므로 후속 패배로 잃지 않는다. 승리 뒤에는 현재 성장과 첫 승리 보상을 반영한 새 준비를 만든다. 모든 재도전은 전역 명령·revision을 유지하여 자금·아이템을 중복 수령하지 않고 재현된다.

## 검증 사례

`packages/core/src/operation.test.ts`는 출격 전 전투 거절과 출격 후 준비 잠금, 고용 견적·취소·배치와 원자 거절, 미장착 수량 판매, 학습 제한, 패배 체크포인트 복원, 지휘관 사망에 따른 계약 제외를 검증한다. 첫 승리→할인 재출격→패배→재도전→재승리의 실제 명령과 전체 JSON 재생에서 추가 EXP·자금·아이템 0을 확인한다. `packages/content/src/operation.test.ts`는 기본 예산, 슬롯·직업·템플릿·상점·보상 참조, 마스터리·태그와 엄격한 저장 필드를 검증한다. 화면·통합 검증 결과는 인수인계 문서에 기록한다.
